# RecruitBook Actor Permission Matrix

This file defines the actor-level permission matrix for RecruitBook methods.

Use this file together with:

* `context/recruitbook_object_catalog.md`
* `context/recruitbook_relationship_catalog.md`
* `context/recruitbook_method_catalog.md`
* `context/security_rules.md`
* `context/diagram_rules.md`

Purpose:

* Account for every method in `context/recruitbook_method_catalog.md`.
* Define which actors may call each method.
* Define which actors must be blocked.
* Define the required security gates for each method.
* Support PlantUML sequence diagrams, activity diagrams, misuse case diagrams, trust boundary diagrams, and implementation planning.

---

# 1. Permission Legend

| Code          | Meaning                                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `ALLOW`       | Actor may call the method directly if listed security gates pass.                                                       |
| `DENY`        | Actor must not call the method.                                                                                         |
| `CONDITIONAL` | Actor may call the method only under strict ownership, verification, consent, visibility, or same-school conditions.    |
| `SYSTEM`      | Method should only be executed internally by RecruitBookApp, database policy, infrastructure, or trusted service logic. |
| `EXTERNAL`    | Method belongs to an external system and should only be invoked through RecruitBook-controlled integration logic.       |
| `N/A`         | Actor does not interact with this method in the system design.                                                          |

---

# 2. Actor Columns

| Actor Column                   | Meaning                                                                                  |
| ------------------------------ | ---------------------------------------------------------------------------------------- |
| `PublicUnauthenticated`        | Visitor with no authenticated session.                                                   |
| `StudentOwner`                 | Authenticated student who owns the affected student profile.                             |
| `OtherStudent`                 | Authenticated student attempting to access another student’s data.                       |
| `PendingCounselor`             | Counselor account that is registered but not verified.                                   |
| `VerifiedCounselorSameSchool`  | Verified counselor linked to the same high school as the student profile.                |
| `VerifiedCounselorOtherSchool` | Verified counselor linked to a different high school.                                    |
| `PlatformAdministrator`        | Platform admin with privileged verification and moderation permissions.                  |
| `ApprovedAdmissionsOfficer`    | Verified and approved admissions officer.                                                |
| `UnverifiedAdmissionsOfficer`  | Admissions officer account that is pending, denied, suspended, or not approved.          |
| `RecruitBookSystem`            | Internal application, policy, database, storage, search, email, or AI integration logic. |

# 3. Global Security Rules

| Rule ID | Rule                                                                                                                                  |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `G-01`  | All sensitive methods require authenticated session unless explicitly public.                                                         |
| `G-02`  | Student-owned profile operations require ownership check.                                                                             |
| `G-03`  | Counselor operations require verified counselor status.                                                                               |
| `G-04`  | Counselor access to student records requires same-school match.                                                                       |
| `G-05`  | Admissions discovery requires approved admissions officer status.                                                                     |
| `G-06`  | Admissions profile access requires current publication, visibility, consent, and authorization checks.                                |
| `G-07`  | AI output cannot be admissions-visible unless accepted by the student and approved by counselor/admin.                                |
| `G-08`  | Student-authored narrative content must remain separate from AI-generated output.                                                     |
| `G-09`  | Transcript files must pass file type and file size validation before storage.                                                         |
| `G-10`  | Privileged actions and denied sensitive access attempts should create `AuditLogEntry`.                                                |
| `G-11`  | Counselor invitation and email verification tokens must be authentic, single-use, unused, unexpired, and bound to the correct target. |
| `G-12`  | Database/API access to student profile data must be protected by `RowLevelSecurityPolicy` where applicable.                           |
| `G-13`  | Shortlisting must not notify the student by default.                                                                                  |
| `G-14`  | Students cannot directly assign counselor-supported or transcript-supported verification status to themselves.                        |
